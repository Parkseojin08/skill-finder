## 결론
- 검색에서 설치 확인까지는 처음 쓰는 사람도 막히지 않는다. 설치 확인 창은 경쟁 도구보다 자세하다(u1, u2).
- 하지만 결과를 믿게 하는 장치들이 기대와 어긋난다. 출처 배지가 사본 저장소로 가고, "N개 숨김 · 보기"는 그만큼 보이지 않고, "주의"가 거의 모든 결과에 붙는다(u1).
- 차별점인 "설치 전에 함께 들어오는 것을 가장 자세히 보여 준다"가 소개 페이지에 없다. 공유할 길(모든 방식의 명령 복사, 링크·묶음)과 출처 공개(공개 저장소·라이선스)도 없다(u2).
- 접근성·반응형은 기본기가 있고, 남은 것은 S급 묶음이다(u3).
- 이미 고친 것: 설치 확인 창이 이전 미리보기나 검사 전 상태로 열리던 문제(u3 P1-1, 커밋 `4b61f7c`).

## 사용자 결정이 필요한 것
- **U1 별 필터에서 공식·파트너 제외**: 지난 점검에서 넘어온 항목이다. 두 검토자가 첫인상 문제로 다시 꼽았다(u1, u2). 추천: 예.
- **"주의" 기준**: "스크립트 포함"만 있으면 정보성으로 내리고, "주의"는 권한 신호(Bash 무제한·훅·셸 주입)에만 붙이자는 제안이다. "pdf tables" 결과의 72%가 "주의"이고, 공식 `pdf`도 "낮음만"에서 빠진다(u1 #6). 위험 규칙 변경이다.
- **같은 이름 저장소 예외(react)**: 한 단어 검색에서 그 저장소의 내부 개발용 스킬이 위를 채운다(u1 #4, D#2130). 예외를 좁히자는 제안이다.
- **README 대체 입력**: README가 없으면 CLAUDE.md·AGENTS.md도 읽자는 제안이다(u1 #5).
- **공개 저장소·라이선스·이슈 경로**: 추천과 awesome 목록에 오를 길이 열린다(u2 #2, U3보다 한 걸음 더).
- **업데이트 서명·변경 기록(U2)**, **npx·macOS 배포**, **영어 지원 범위**: "하지 말 것" 목록(`ui-debate-final-report.md:128`)을 바꾸는 일이다.
- **팀 프리셋 내보내기·가져오기**: 보류됐던 일괄 기능이다(u2 #6, #14).
- **즐겨찾기·저장소 숨기기(U7)의 저장 위치**: 포트를 바꾸면 localStorage가 비어 보이므로 서버 DB를 권한다(u3).
- **카드 점수 숨김·기본 쪽당 10개**(u1 #17), **검색마다 기록 남기기(pushState)**(u3 P2-1).
- **Claude Code 안에서 쓰는 읽기 전용 CLI**, **공유 링크 정적 페이지**(u2 P1·P2): 원칙의 경계에 있는 제안이다.
