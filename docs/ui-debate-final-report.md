# Skill Finder UI·추가 기능 토론 — 최종 보고서

패널 5명(p1 UX·정보 구조, p2 보안·신뢰, p3 파워 유저, p4 처음 쓰는 사용자·접근성, p5 제품·유지비)이 2라운드씩 토론했다. 사회자는 핵심 숫자와 코드 근거를 직접 다시 확인했다(아래 "2라운드 검증").

## 한 줄 요약
1. 가장 큰 구멍은 기본 필터(주의까지)에서 보이는 스킬 **1,226개**다. 이 스킬들은 플러그인 **95개**에 들어 있고, 하나를 설치하면 같은 플러그인의 **위험 높음** 스킬도 함께 설치된다. 그런데 확인 창은 이것을 보여 주지 않는다. 다섯 패널 모두 이 문제를 1순위로 꼽았다.
2. 스킬 방식은 **검사한 커밋 그대로 설치**할 수 있다. 번들 skills CLI가 커밋 SHA 주소를 받기 때문이고, 약 25줄이면 된다(실제 실행은 아직 확인하지 않았다). 플러그인 방식은 커밋을 고정할 수 없다. 그래서 확인 창에 한 줄로 알리고, 설치한 뒤에 커밋을 비교한다.
3. 새 zip을 새 폴더에 풀면 색인과 토큰이 사라진다. 데이터 위치를 옮겨 버전끼리 공유하려면 DB **버전 내리기 보호**를 꼭 함께 넣어야 한다.
4. 화면 쪽 합의는 다섯 가지다: 카드를 진짜 링크로, 주소에 검색어, "설치됨" 표시, 설치됨 화면과 색인 연결, 설치 뒤 바뀜 표시. 설치 뒤 관리는 **표시만** 하고 실행(업데이트·켜기·끄기)은 미룬다.
5. 사용자의 실제 검색 기록은 **0건**이다. 숫자로 판단해야 하는 기능(비교, 빈 결과 우선순위 등)은 기록이 쌓인 뒤에 정한다.

- p4: 접근성(2-2)은 P1 중 맨 앞이어야 한다(다수는 2-1 파일 나누기 뒤로).
- p5: 검색 화면 나누기(2-1)를 기능보다 먼저 해야 한다. 다른 패널은 이 순서를 직접 다루지 않았다.
